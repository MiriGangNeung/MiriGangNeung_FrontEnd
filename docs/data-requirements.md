# Data Requirements

화면별로 실제 서비스가 되려면 어떤 데이터가 필요한지 정리한 문서. 화면별 UI 스펙(레이아웃/색/타이포)은 루트 `README.md`의 "Screens" 섹션이 원본이며, 여기서는 반복하지 않는다.

## 화면 1 — BackgroundPicker (배경 선택)

- **입력 데이터**: 장소 목록(`Place[]`) — id, name, region, tags, category, 대표 사진 URL.
- **카테고리 필터**: `전체/필터/해변/맛집/자연` 탭에 대응하는 `cat` 값. 현재는 하드코딩된 5개 탭(`data/places.ts`의 `TABS`)이지만, 실제로는 장소 데이터에서 파생되는 동적 카테고리 목록일 수 있음.
- **사진**: 지금은 `ImageSlot` placeholder. 실제로는 장소당 최소 1장의 대표 이미지 URL 필요(4:3 비율).
- **사용자 입력**: 최대 3곳 선택(`picks`), 찜 여부(`liked`) — 찜은 picks와 별개로 유지되는 사용자 설정.

## 화면 2 — OnePickConfirm (원픽 확인)

- 화면 1에서 고른 `picks` 중 정확히 1곳을 "원픽"으로 지정(`onePick`) — 합성 배경으로 사용됨.
- 추가 서버 데이터 없음(화면 1 데이터의 부분집합만 사용).

## 화면 3 — PhotoUpload (사진 합성)

- **사용자 업로드**: 얼굴이 보이는 사진 1장(JPG/PNG, 10MB 이하).
- **합성 Job**: 업로드 후 "합성 Job"을 생성해야 함 — 서버가 원픽 배경 + 사용자 사진을 받아 비동기로 합성.
  - 생성 시 즉시 `jobId` 반환, 이후 상태를 폴링(`queued → running → done`).
  - 진행률(`progress` 0~100 또는 5단계 스테이지 인덱스)과 완료 시 결과 이미지 URL 필요.
  - 현재 프로토타입은 `COMPOSE_STAGES` 5단계를 1.5초 간격 타이머로 가짜 진행시키는 것 — 실제로는 이 자리를 폴링 응답으로 대체.
- **동의 항목**: 두 체크박스(AI 합성 사용 동의, 결과가 실제와 다를 수 있음 확인) — 실제 서비스에서는 동의 이력을 사용자별로 저장해야 할 수 있음.

## 화면 4 — CompositeResult (합성 결과)

- 완료된 합성 Job의 결과 이미지 URL, 생성 시각.
- 원픽 장소의 상세 설명(현재 하드코딩된 한 문장 — 실제로는 장소 데이터의 `description` 필드 필요).

## 화면 5 — CourseOptions (코스 조건)

- **사용자 입력만 필요**: 여행 타입(1~2개), 동행 유형(1개), 기간(당일/1박2일/직접설정 — custom 선택 시 시작일/종료일).
- 서버로 보낼 코스 생성 요청의 입력값 — 아직 서버 호출 없음(다음 화면에서 결과를 표시하기 위한 입력 수집 단계).

## 화면 6 — CourseResult (코스 결과 + 지도)

- **코스 생성 결과**: 순서가 있는 정거장 목록(`CourseStop[]`) — 각 정거장은 이름, 방문 시각, 체류 시간, 혼잡도, 메모, 위경도(지도 표시용), 원픽 여부.
- **지도**: Leaflet + OpenStreetMap, 정거장 좌표는 실제 강릉 지역 좌표여야 함(하드코딩 금지, 지도 왜곡 방지).
- 코스 생성은 화면 5의 입력(원픽, 후보 장소, 타입, 동행, 기간)을 서버가 받아 최적 동선을 계산해 반환하는 것을 전제로 함 — 현재는 `data/places.ts`의 정적 `COURSE_STOPS` 4곳으로 시뮬레이션.

## 요약

| 데이터    | 현재 소스                  | 실제 서비스 소스                |
| --------- | -------------------------- | ------------------------------- |
| 장소 목록 | `data/places.ts` 정적 배열 | 장소 API (사진/설명 포함)       |
| 합성 Job  | 타이머로 가짜 진행         | 비동기 Job 생성 + 폴링 API      |
| 코스 결과 | 정적 4개 정거장            | 코스 생성 API(사용자 조건 기반) |

이 표는 `docs/api-spec-draft.md`의 엔드포인트 초안과 1:1로 대응한다.
